# Flight sandbox audit and polish

Follow-up audit of the baseline repair work, 2026-09-24. Scope: flight usability, physics command ordering, course feedback, UI ownership, save/world preparation, and teardown diagnostics.

## Findings fixed

| Priority | Finding | Repair and evidence |
| --- | --- | --- |
| P1 | Registering a replacement for an open menu left the original in the stack; `close_all_menus()` could loop indefinitely. | Replace the existing stack entry, preserve its visibility, and free the old control. Regression opens, replaces, and closes the menu. |
| P1 | The example restored save data before preparing its destination, so a failed world load could leave a mismatched live state. | `request_load_slot()` validates and holds an in-memory snapshot, prepares the destination, then restores data only on success. Smoke tests reject unknown destinations and exercise a known destination that fails to load. Scene and wallet remain unchanged on failure. |
| P1 | Malformed nested save data and unsupported schema versions could reach live restoration. | Preflight validates snapshot sections, entity/component envelopes, metadata values, checksum type, and schema version before mutation. Component-specific field validation remains owned by individual components. |
| P2 | Braking fought held thrust and could leave residual speed; physics reset could inherit forces from a prior callback. | Apply each tick's forces within `_integrate_forces()`, give braking priority, and return immediately after resetting state. The regression holds thrust throughout braking. |
| P2 | Hull inertia made pitch, yaw, and roll response inconsistent. | Convert the requested angular acceleration into torque using the rigid body's inertia tensor. Physical collisions remain enabled. |
| P2 | Switching away left flight active and there was no usable exit/restart menu. | Focus loss pauses simulation and releases the cursor. Native buttons resume, restart, or exit, with keyboard focus and a readable small-window layout. |
| P2 | HUD replacement detached controls without freeing them; closing menus also released a preexisting pause. | Dispose replaced HUDs, make same-instance assignment safe, and restore prior pause/mouse state. Added ownership and pause regression tests. |
| P2 | Loader rollback trusted mutable global world metadata instead of the attached world. | Track `active_world_id` separately and use it for rollback. Regression changes saved metadata before requesting travel. |
| P2 | Editor plugin detached its toolbar without freeing it. | Queue the toolbar for deletion and explicitly unregister the edit button from its container during teardown. |

## Follow-up repairs

- Entity and spawn-tracker managers clear their global instance reference when deleted, only if they still own it. Regressions verify that deleting an older manager cannot clear a newer replacement.
- Course completion interpolates the last gate crossing within the physics tick, so equivalent trajectories produce the same finish time across different tick sizes.
- Course start detection measures cumulative movement from the starting position; very slow movement no longer prevents the timer from starting indefinitely.

## Presentation and course feedback

- Replaced the block hull with a tapered silhouette, cockpit, wings, engines, and thrust exhaust cues. Added wing collision shapes.
- Added an ordered six-gate course with a timer, completion state, and restart. Swept plane intersections catch fast crossings; reverse crossings and passes outside the opening do not count.
- Added next-gate brackets, range, and offscreen guidance. The flight reticle now projects the ship's forward direction instead of assuming the chase camera points straight ahead.
- Reworked the HUD hierarchy, speed bar, stopping-distance estimate, and control hints. Cached panel styling avoids allocating style resources every frame.
- Enabled 4× MSAA and verified the normal view at 1280×800 and pause view at 960×600. Screenshots live in `flight_sandbox/preview.png` and `flight_sandbox/preview_pause.png`.

## Verification

- GUT reports **300 tests passing / 772 assertions**.
- Standalone flight, course, and pause integration runner reports **30 checks passing**.
- Example scene smoke test reports **zero failures**, including successful cross-world restoration, unknown destination rejection, and failed destination preparation without wallet changes.
- Screenshots were generated by the running game and visually inspected, including the pause menu at the minimum supported window size.
- Runtime still needs human flight-feel testing; automated tests establish behavior, not whether a controller feels enjoyable.

## Remaining issues and boundaries

The broad GUT/editor run still retains script/font/theme resources at shutdown and can stall on this Windows runner. Verbose GUT diagnostics include retained GUT scripts and framework resources; no single root cause has been established. A separate minimal project using the same Godot 4.4.1 and GUT 9.4.0 completed both editor import and a one-test run with exit code zero and no retained-resource warnings, so the runner alone does not reproduce the issue. Clearing manager instance references did not resolve the broad-run shutdown stall. The specific HUD/menu/toolbar ownership leaks above were repaired, but this is not a claim that all teardown leaks are resolved. Bounded validation stops stalled processes after they finish reporting results. The standalone flight runner and screenshot capture exit normally.

Save checksum mismatches retain the existing warning behavior for compatibility. Nested component-specific payloads require their own validation/migrations; the new envelope checks do not make arbitrary save data safe to trust. The example's preparation coordinator is the correct entry point for world-aware quick-load; the lower-level SaveSystem API restores data only.

The ship remains independent of RPG entities and saves. Combat, trading, persistent ship state, and jump navigation are outside this polish pass.
